## 0. 프로젝트 개요
- **목적**: 개별 종목/ETF/섹터/지수의 펀더멘털을 **정적(특정 시점)**과 **동적(시간에 따른 변화)** 두 축으로 분석
- **시장**: 한국(코스피/코스닥) + 미국, 크로스마켓 비교 가능(예: KOSPI vs S&P500)
- **배포**: Streamlit Cloud
- **AI 사용 원칙**: 실행 단계(앱 구동 시)는 AI API 원칙적으로 미사용. 단, 자동 크롤링이
  구조적으로 불안정한 항목(섹터/지수 평균 등)은 **사람이 주기적으로 AI 검색을 통해 수동
  갱신하는 JSON 파일**로 대체 가능 (v2에서 신규 확정 — 아래 §10 참고)

## 1. 정적 분석 (Static)
특정 시점 기준 스냅샷 지표.

**개별 종목**: PER, PBR, PSR, EV/EBITDA, 배당수익률 / ROE, ROA, 영업이익률, 순이익률 / 부채비율, 유동비율, 이자보상배율 / FCF, FCF Yield 등

**ETF**: 운용보수(TER), 상위10종목 비중, 섹터/국가 비중, 편중도(HHI), 가중평균 PER/PBR, AUM, 거래대금/스프레드, 분배수익률

---

## 2. 동적 분석 (Dynamic) — 다중 시간축

| 주기 | 적용 대상 | 비고 |
|---|---|---|
| **MoM(월간)** | 가격성/시장 데이터만 (주가, 거래대금, 컨센서스 EPS 수정률, 수급) | 재무제표는 월단위 미발표 → 재무지표는 MoM 비활성 |
| **QoQ(전분기 대비)** | 매출, 영업이익, 이익률, ROE 등 | ⚠ 계절성 왜곡 가능 — 표기 시 주의문구 병기 |
| **동일분기 YoY** | 매출, 이익, EPS, 배당 등 | 계절성 제거된 핵심 성장률 지표 |
| **동일분기 YoY Rolling(4~8분기 연속 시계열)** | 위와 동일 | **핵심 지표** — 성장률의 가속/감속(2차 미분 개념) 판정용 |

### 밸류에이션 밴드 표기 원칙
- `%ile`(백분위) 단독 표기는 혼동 유발 → **"평균 대비 % 차이" + "구간 라벨"을 함께 표기**
- 구간 라벨: 0~20% 매우저평가 / 20~40% 저평가 / 40~60% 평균 / 60~80% 비싼 편 / 80~100% 매우비쌈
- 예: `PER 22.8배 (5년 평균 18.5배 대비 +23%, 비싼 편)`

## 3. 비교 축(Benchmark Layers) — 3단 구조 (N=1, 단일 종목 분석 시)
1. 자기 자신 시계열 (동적 분석 기준)
2. 동종 섹터/산업 평균 (Peer Group)
3. 시장 전체 지수 또는 대표 ETF

→ 정적 표: 종목값 / 섹터평균 / 지수(ETF)평균 + 괴리율(%)
→ 동적 표: 종목 변화 / 섹터 변화 / 지수 변화 + 상대강도

**섹터/지수 벤치마크는 지수(INDEX) 또는 대표 ETF 둘 다 선택 가능하게 설계** (ETF는 상장일이 짧으면 데이터 제한되므로 지수도 병행 지원)

> **v2 결정사항**: 섹터/지수 평균은 실시간 자동 크롤링이 구조적으로 불안정함이 v1에서 확인됨
> (KRX/pykrx/FnGuide 등 전부 실패 또는 접근 제한). → **JSON 수동 갱신 파일 방식**으로 확정
> (자세한 내용 §10 및 02_DATA_SOURCE_SPEC.md 참고)

## 4. Entity 통일 스키마 (크로스마켓 비교 지원)
비교 대상을 4종류로 추상화하여 동일한 지표 스키마를 공유:
- `STOCK`, `SECTOR`, `INDEX`, `ETF`

→ 종목-섹터, 종목-지수, 지수-지수(한국 vs 미국), ETF-ETF 등 모든 조합이 같은 로직으로 비교 가능.

### 크로스마켓 처리 이슈
| 이슈 | 처리 |
|---|---|
| 통화 | 비율지표(PER, ROE, 성장률 등)는 환율 영향 없음(그대로 비교). 절대금액 지표(시총, 매출 규모)만 환율 적용 여부 선택 |
| 환율 적용 UI | 메인화면 체크박스 — **단, 비율지표에는 노출 안 함. 절대금액 지표(정적, "규모 비교" 용도)에만 노출**. 동적 분석(변화율)에는 원칙적으로 미적용(환율 효과로 인한 왜곡 방지) |
| 회계기준 차이 | 표준화된 지표(PER, ROE 등) 레벨에서만 비교, 세부 회계기준 차이 무시 |
| 섹터 분류체계 차이 | GICS로 통일 매핑 필요 (한국 WICS ↔ GICS 매핑 테이블 — **v1에서도 미확정, 여전히 미해결**) |
| 결산월/발표시차 | 최신 발표 분기 기준 정렬(TTM 또는 최근 분기 통일) |

## 5. 비교 대상 개수(N)에 따른 리포트 템플릿 분기

| N | 템플릿 | 비고 |
|---|---|---|
| **N=1** (종목/지수 1개) | 본문형: 정적(vs섹터/vs지수) + 동적(vs섹터/vs지수) + 종합매트릭스 | §3 구조 사용 |
| **N=2** (A vs B 직접비교) | 통합형: 한 테이블에 A값·B값·차이·배수·Gap 컬럼 배치. **리포트를 두 번 반복하지 않음** | §6 상세 |
| **N≥3** | **미지원** — 사용자가 2개씩 pairwise로 여러 번 조회하도록 안내. 다수 종목 랭킹은 별도 "스크리너" 기능(추후 설계)에서 처리 | |

## 6. N=2 비교 모드 상세 설계 (A vs B)

### 6-1. 정적 비교 테이블
| 지표 | A값 | B값 | 차이(A-B) | 배수(A/B) | 우위 |
|---|---|---|---|---|---|

> **v2 결정사항**: 한국·미국 크로스마켓 비교 시, 양쪽 시장에서 모두 확보 가능한
> **공통 지표만** 이 표에 포함 (한쪽 시장에만 있는 지표는 N=1 단일종목 화면에서만 노출).
> 공통 지표 목록은 02_DATA_SOURCE_SPEC.md에서 확정.

### 6-2. 동적 비교 테이블
| 분기 | A 값 | B 값 | Gap(A-B) |
|---|---|---|---|
Gap 컬럼만으로 격차 확대/축소 시점을 숫자로 즉시 확인 가능하도록 설계. 표 아래에 A/B 각각
다른 색 선 그래프 병기.

### 6-3. 멀티플(PER) 프리미엄 — 시계열 동행성 참고 섹션
- PER 밴드 위치의 분기별 변화와 이익 YoY의 분기별 변화를 같은 분기축에 나란히 놓고
  동행/디커플링 여부를 관찰
- 인과관계 단정 금지: "때문이다" 대신 "동행성/디커플링 관찰" 톤 유지

### 6-4. 종합 판정 — 투자판단 참고 프레임 (추천이 아닌 판단재료 제공)
1. **포지션 유형 분류**: 각 entity를 유형화, 강점·유의점 병기
2. **시나리오별 시사점**: 조건부 해석 표 (예측이 아닌 조건-결과 나열)
3. **판단 시 함께 볼 요인(리포트 범위 밖 명시)**: 환율 전망, 금리/통화정책, 지수 내 편중도, 지정학 리스크 등

## 7. 표기/포맷 규칙

| 항목 | 규칙 |
|---|---|
| 숫자 형식 | 소수점 2자리 통일, 천단위 콤마, 지표명에는 단위 표기 안 함 → **숫자 뒤**에 단위(%,배 등) 접미사 |
| 결측치(N/A) | 단위 표기 없이 "N/A"만 표시. 벤치마크 표에서는 해당 행 자체를 생략 |
| 음수 | 빨간색으로 표시 |
| 화살표(↑↓) | Streamlit 웹 UI: 네이티브 delta 대신 커스텀 카드로 색상 직접 제어(음수=빨강) |
| "→"(흐름 표시, 인과 아님) | 일반 텍스트 문자로 취급 |
| 실데이터 vs 샘플 구분 | 실데이터가 아닌 값에는 반드시 "(샘플)" 라벨 병기, 실데이터에는 기준일(as_of) 표기 |

## 8. 진행 중 확정된 항목 (v1 → v2)

1. **공통 지표 스키마**: 밸류에이션(PER/PBR/PSR/EV-EBITDA/배당수익률), 수익성(ROE/ROA/영업이익률/순이익률),
   건전성(부채비율/유보율/유동비율/이자보상배율), 성장성(매출·영업이익·EPS YoY), 현금흐름(FCF/FCF Yield) —
   단, **한국·미국 양쪽에서 실데이터 확보 가능한 지표와 한쪽에만 가능한 지표가 다름** (상세는 02번 문서)
2. **섹터 분류 매핑**: 여전히 미확정 (WICS↔GICS) — v2에서도 보류, 우선순위 낮춤
3. **동적 분석 lookback**: 밸류에이션 밴드 5년, YoY Rolling 8분기 기본값(4~12분기 조정 가능)으로 v1에서 확정, 유지
4. **데이터 소스**: v1에서 pykrx(전면 실패), FnGuide(robots.txt 차단) 확인됨 →
   **v2는 데이터 소스를 역할별로 재설계** (02_DATA_SOURCE_SPEC.md)
5. **점수화/등급**: 미착수
6. **화면 와이어프레임**: v2에서 01_UI_SPEC.md로 확정 예정
7. **이상치/결측 처리**: N/A 그대로 노출, 임의 필터링 없음 — v1에서 확정, 유지

## 10. v2 신규 원칙: 데이터 획득 방식 3분류

| 분류 | 정의 | 처리 방식 |
|---|---|---|
| **A. 실시간 자동 (검증됨)** | 개별 종목 조회 시마다 앱이 스스로 크롤링 | 네이버금융(한국), yfinance(미국) — v1에서 안정성 확인됨 |
| **B. 수동 주기 갱신 (JSON)** | 자동화가 불안정하거나 비용이 큰 데이터 (섹터/지수 평균 등) | 사람이 AI 검색 등으로 조사 → JSON 파일 → GitHub 업로드 → 앱은 읽기만 함 |
| **C. 미지원 (N/A 유지)** | A/B 둘 다 불가능하거나 우선순위 낮은 항목 | 화면에 N/A로 유지, 추후 재검토 |

이후 모든 지표는 02_DATA_SOURCE_SPEC.md에서 A/B/C 중 하나로 명시적으로 분류됨.
